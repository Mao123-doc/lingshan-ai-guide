## 摘要与项目全景

在生成式人工智能（Generative AI）与文旅数字化深度融合的浪潮下，主流导览产品多局限于“单向事实问答”与“无约束文本生成”。然而，真实景区场景呈现出高度的**物理不可逆性**与**时空强约束性**：游客在特定时间点入园，面临有限的时间预算、复杂的路网拓扑、刚性的演艺开演时刻以及特殊人群（如老人、轮椅出行者）的体力与通行限制。通用大模型在面对此类任务时，频频产生“时间穿越”、“推荐轮椅攀爬千级台阶”、“安排已散场演艺”等时空错位，离线评测合规率仅为 30.0%。

针对上述行业断层，本项目研发了“灵小禅·可信文旅决策智能体”。系统采用**“双引擎协同解耦”架构**：
1. **语义理解与知识检索层**：构建基于 `Promise.all` 驱动的 Vector + Structured + Keyword 三路并行检索管道，结合 Reciprocal Rank Fusion ($k=60$) 与 Cross-Encoder 深度重排，搭配端到端 Fact Contract（事实合约）校验机制与官方权威指南（`knowledge_guide.txt`）硬置顶仲裁。在 50 题权威基准测试中，实现 **96.0% (48/50)** 的 Fact Contract 通过率与 **0.970** 的事实召回率（受控消融实验特定轮次完整方案观察值为 **98.0%**）；
2. **物理时空运筹决策层**：将游客口语化诉求解构为 13 维时空状态向量 $\mathbf{s}$（场景槽位基准测试提取准确率 **100.0% (40/40)**），在当前包含 23 个路线节点与 30 条当前登记道路边的数字孪生路网拓扑图上（31 条为待补齐核验的目标口径），依托**倒排时空推演（Backward Scheduling）**计算演艺关键节点，采用 **24 候选宽度 Beam Search** 运筹求解动线，并由独立的 **14 项形式化守恒仲裁器（Route Validator）**实施熔断机制。在 60 组边界测试中实现了 **100.0% (60/60)** 形式化合规，物理硬违规恒为 **0** 次；
3. **轻量化边云交付与人机协同**：运筹内核采用轻量化图算法，单台 4 核 8G 边缘服务器针对纯路线规划接口经 Locust 仿真压测实测 **202.4 QPS**（P50=7.8ms，P95=13.4ms，0 错误率，通过 `worker_threads` 线程池与 I/O 隔离；不包含 LLM、ASR、TTS、图像识别全链路），单景区年综合算力与运维成本测算低于 **1.5 万元**（约 1.39 万元/年），3~6 个月收回前期投入（情景假设测算）；前端设计集“证据追溯抽屉”、“高德/百度实景导航调起”与“Live2D 汉服数字人情绪状态机”于一体的双屏交互闭环。

本项目在算法上探索了确定性与生成式的有机统一，并沉淀了全链路可追溯的工程评测证据链。

## 第一章：项目背景与行业痛点

### 1.1 文旅数字化困局：从“知识展示”到“真实决策”的鸿沟
随着全域旅游与智慧景区建设的纵深推进，5A/4A 级景区的硬件设施（如智能闸机、导览牌、大屏）已基本普及。然而，游客在游览过程中的实际决策体验依然面临巨大鸿沟：
- **静态导览信息过载**：景区官方小程序往往充斥着海量的景点介绍文本与静态 PDF 地图，游客难以在短时间内提炼出契合自身节奏的游览动线；
- **决策约束高度耦合**：一次游览决策往往交织着多项变量——入园时间、离园死线、重点演艺场次、家庭成员行动能力以及排队状况。普通游客缺乏景区全域时空全局认知。

### 1.2 大模型落地文旅场景的挑战：“时空幻觉”
通用大模型（如 GPT-4o、DeepSeek）具备强大的自然语言交互能力，文旅行业纷纷尝试将其包装为“AI 导游”。然而，在涉及真实时空决策时，通用大模型表现出致命的局限性：
1. **时间守恒计算困难（Temporal Misalignment）**：大模型对物理时间感知较弱，在规划中可能出现跨越距离过长但预估时间过短的现象（如声称“5 分钟走完 1.4 公里”）；
2. **演艺场次与排队盲区**：演出往往具有固定的开演时间与入场规则。大模型缺乏提前 15~20 分钟检票停检排队的刚性约束概念，导致游客狂奔依然吃闭门羹；
3. **无障碍拓扑感知不足（Spatial Agnosticism）**：模型难以精准区分台阶与轮椅通道的物理限制。盲目推荐推轮椅的老人攀爬数百级台阶，存在极大的人身安全与摔伤隐患；
4. **防御拒绝机制不足**：当游客提出时间预算上不可能完成的诉求时（如“20 分钟逛完灵山”），大模型往往过度谄媚，强行编造看似流畅但实际超时的路线，缺乏清晰的拒绝与降级策略。

### 1.3 文旅痛点探索性预调研数据剖析与景区 B 端痛点
团队于无锡灵山胜境景区现场及线上社群开展了面向 50 份样本的文旅痛点探索性预调研（Exploratory Pilot Pre-Survey, $n=50$，包含 35 份现场纸质问卷与深度访谈，以及 15 份定向回访，详见 `05_现场演示与用户调研/pre_survey_summary.md`）。统计结果揭示了明确的量化痛点与需求刚性：
- **演艺错配痛点 (82.0%)**：41/50 的受访游客表示曾因“预估耗时不足”或“排队时间过长”而遗憾错过既定演艺；
- **无障碍阻断痛点 (66.0%)**：33/50 的受访游客曾遭遇导览误导进入陡坡长阶被迫折返；若仅以受访群体中存在长辈或推车行动受限诉求的样本（$n=30$）为分母，遭遇台阶陡坡阻断折返的比例为 **93.3% (28/30)**；
- **事实性幻觉痛点 (74.0%)**：37/50 的受访游客在使用各种 AI 助手时，曾遇到票价或开放时间等事实错误；
- **可信决策导览意愿 (90.0%)**：45/50 的受访游客表示愿意使用一个能自动规避台阶、预留排队缓冲并在超时后动态重规划的智能导览。

*注：本调研属于场景探索性预调研，旨在定性与定量捕捉典型文旅痛点并指导算法设计，不作为全量游客大规模双盲统计学推断。*

同时，在景区 B 端（运营管理方）视角下，传统 AI 的时空幻觉直接加剧了现场客流拥堵、剧场前踩踏隐患与客服投诉激增。

#### 代码级防越权门禁机制 (FORBIDDEN_LLM_FIELDS)
为了从根源上杜绝大模型越权编造路线，系统在意图层与运筹层之间设立了代码级门禁拦截网关：
```typescript
// 1. 严格禁止大模型生成的越权字段黑名单
export const FORBIDDEN_LLM_FIELDS = [
  "steps",          // 禁止 LLM 编造景点访问序列
  "feasible",       // 禁止 LLM 伪造时空可行性结论
  "route_summary",  // 禁止 LLM 自行计算总耗时与里程
  "coordinates"     // 禁止 LLM 虚构经纬度与几何连通
] as const;

// 2. 意图解析网关中的形式化拦截与白名单重构
export function sanitizeSceneState(rawLLMOutput: unknown): SceneStatePayload {
  const parsed = RawSceneSchema.parse(rawLLMOutput);
  for (const forbiddenKey of FORBIDDEN_LLM_FIELDS) {
    if (forbiddenKey in parsed) {
      logger.warn(`[SECURITY_GATEWAY] 拦截到大模型越权字段: ${forbiddenKey}，强制剔除`);
      delete parsed[forbiddenKey as keyof typeof parsed];
    }
  }
  // 3. 仅向运筹引擎移交严格合规的 13 维时空状态画像
  return ValidatedStateSchema.parse(parsed);
}
```
通过该门禁，系统剥夺了大模型生成路线步骤（`steps`）与可行性结论（`feasible`）的权力，所有时空计算与物理连通性由运筹引擎享有绝对排他性求解权。

### 2.2 核心技术选型一览
1. **知识检索引擎**：
   - 密集语义检索：`BAAI/bge-large-zh-v1.5`；
   - 重排模型：`BAAI/bge-reranker-large`（Cross-Encoder）；
   - 融合机制：Reciprocal Rank Fusion ($k=60$)；
   - 异步架构：`Promise.all` 驱动三路并行检索。
2. **时空运筹引擎**：

3. **大语言模型底座**：
   - 意图与生成：采用 `deepseek-chat` / `deepseek-flash` 云端按量计费接口。

## 第三章：知识增强检索机制（Hybrid RAG）

### 3.1 基于 Promise.all 驱动的三路并行检索原理
针对文旅场景的特殊性，灵小禅设计了三路检索架构：
- **向量检索 (Vector Retrieval)**：基于余弦相似度召回 Top-8 候选片段，处理泛化口语表达；
- **结构化检索 (Structured Retrieval)**：提取实体匹配结构化 JSON 知识库，处理票价、时刻等确定性数据；
- **关键词检索 (Keyword Retrieval / BM25)**：利用倒排索引进行词项匹配，应对生僻专有名词。

通过 `Promise.all` 并行触发，将整体检索时延缩短至单路最慢通道耗时（约 120ms）。

### 3.2 融合与重排 (RRF & Cross-Encoder)
系统引入 **倒数排名融合（RRF）** 对三路结果进行初步融合，平滑常数 $k=60$：
$$\text{RRF\_Score}(d \in \mathcal{D}) = \sum_{m \in M} \frac{1}{60 + r_m(d)}$$
随后，将 Top-12 候选送入 `bge-reranker-large` 交叉编码器进行深度重排。2026-09-17 历史合格消融观察到，引入重排后，Fact Contract 通过率由 90.0% 提升至 98.0%（边际跃迁 $+8.0$ 个百分点），提示其有助于缓解多通道打分量纲偏置；2026-09-21 重跑因 provider 失败、7 组质量门禁均未通过，不能用来重新证明该增益，该历史单次结果不外推为普遍因果结论。

### 3.3 事实合约（Fact Contract）核验与官方指南置顶
系统引入了“事实合约”机制，基于官方指南（`knowledge_guide.txt`）对生成的关键数值进行强制置顶核对校验。当多信源冲突时，以官方指南为唯一最高准则强制覆盖，并在 `Trace` 日志中完整记录执行链路，实现透明可复现。

## 第四章：物理时空双约束运筹引擎

### 4.1 13 维时空状态解构
系统将游客口语转化为 13 维状态向量 $\mathbf{s} \in \mathcal{S}$：
$$\mathcal{S} = \langle P_{loc}, T_{start}, \Delta T_{budget}, C_{crowd}, M_{mobility}, E_{pref}, I_{interest}, V_{must}, V_{visited}, F_{flex}, L_{lang}, D_{device}, A_{auth} \rangle$$
在 40 组典型多约束测试集中，槽位抽取准确率达到 **100.0% (40/40)**，关键缺失识别率 **100.0%**。

### 4.2 倒排时空约束推演（Backward Scheduling）
针对演艺活动的强时效性，系统设计了倒排时空约束推演算法：

```text
算法 1：倒排时空约束推演算法 (Backward Scheduling)
--------------------------------------------------------------------------------
输入：游客状态 S，路网 G=(V, E)，演艺时刻表 T_perf，离园时间 T_exit
输出：最优动线 P* 或 不可行诊断证明 C_infeasible
1. 初始化刚性时间锚点：T_cur <- T_exit
2. 若存在演艺偏好 S.E_pref：
   - 获取演艺时间窗口 [t_start, t_end] 与前置排队安检缓冲 Δt_buffer <- 20 min
   - 若 t_end > T_exit，触发优雅降级，剥离演艺偏好
   - 锚定演艺最晚到达时刻：T_arrive_perf <= t_start - Δt_buffer (如 14:00 演出锁定 13:40 到)
3. 基于 G 执行反向时间窗衰减：
   - 对前序景点 v，计算最晚离开时刻与到达时刻
4. 将前向搜索起点 P_loc 与反向时间窗求交集，确定出发时刻 T_start (如逆推出发时刻 11:00)
5. 若交集为空，输出诚实拒绝；否则在可行子图上执行 24 宽 Beam Search 求解 P*
--------------------------------------------------------------------------------
```

### 4.3 多目标 Beam Search 运筹
在构建的无障碍图上，采用束搜索（Beam Search，宽度 $B=24$）探索动线：
$$\max \quad U(\mathcal{P}) = \sum_{v \in \mathcal{P}} \big( 1000 \cdot \mathbb{I}_{must} + 500 \cdot \mathbb{I}_{perf} + 25 \cdot \text{Score}_{int} \big) - 5 \cdot \text{Cost}(\mathcal{P})$$
效用函数综合考虑必达点、演艺覆盖、兴趣相似度，以及包括步行距离、疲劳度在内的负向惩罚代价。

## 第五章：14 项形式化守恒仲裁器（Route Validator）

规划生成的动线需经过 14 项仲裁器的硬规则校验：

| 规则编号 | 仲裁规则名称 | 形式化数学/逻辑断言 | 违规处理机制 |
| :--- | :--- | :--- | :--- |
| **VAL-01** | 时间单调递增律 | $\forall i, \, T_{arrive}(v_{i+1}) \ge T_{depart}(v_i) + \text{WalkTime}(v_i, v_{i+1})$ | 物理熔断重排 |
| **VAL-02** | 总时长闭环守恒 | $\sum_{i} (\text{StayTime}(v_i) + \text{WalkTime}(e_i)) \le \Delta T_{budget}$ | 诚实拒绝/修剪 |
| **VAL-03** | 闭园时间硬边界 | $T_{depart}(v_{last}) \le T_{closing\_time} - \Delta t_{exit\_buffer}$ | 强制提前返程 |
| **VAL-04** | 轮椅坡度舒适上限 | $\forall e \in \mathcal{P}, \, M_{mob}=\text{limited} \implies \text{Slope}(e) < 2.5^\circ$ | 剔除大坡度边 |
| **VAL-05** | 台阶物理阻断 | $\forall e \in \mathcal{P}, \, M_{mob}=\text{limited} \implies \text{StepCount}(e) = 0$ | 物理路径阻断 |
| **VAL-06** | 演艺前置排队缓冲 | $T_{arrive}(e_{perf}) \le T_{start}(e_{perf}) - 15\text{min}$ | 逆向压缩前序 |
| **VAL-07** | 演出时间完全覆盖 | $T_{depart}(e_{perf}) \ge T_{end}(e_{perf})$ | 禁止中途退场 |
| **VAL-08** | 必达景点全覆盖 | $V_{must} \subseteq \mathcal{V}(\mathcal{P})$ | 强惩罚未达点 |
| **VAL-09** | 拓扑连通性闭环 | $\forall i, \, (v_i, v_{i+1}) \in \mathcal{E}(\mathcal{G})$ | 排除断头路线 |
| **VAL-10** | 重复回头路惩罚 | $\text{Count}(v_i \in \mathcal{P}) \le 1 \quad (\forall v_i \notin \{P_{start}, P_{end}\})$ | 惩罚环路冗余 |
| **VAL-11** | 单段步行疲劳上限 | $\forall e \in \mathcal{P}, \, \text{WalkDuration}(e) \le 45\text{min}$ | 插入中途休息 |
| **VAL-12** | 全日体力总消耗 | $\sum_{e \in \mathcal{P}} \text{Dist}(e) \le \text{MaxDistance}(M_{mob}, C_{crowd})$ | 超限降级电瓶车 |
| **VAL-13** | 营业开放窗口匹配 | $\forall v \in \mathcal{P}, \, [T_{arrive}(v), T_{depart}(v)] \subseteq [T_{open}(v), T_{close}(v)]$ | 跳过闭馆景点 |
| **VAL-14** | 交通接驳闭环律 | $\text{NeedShuttle}(\mathcal{P}) \implies \text{ValidBoarding}(\mathcal{P})$ | 校验站点连通 |

在针对 60 组边界案例的独立验证测试中，系统实现了 **100.0% (60/60)** 校验合规与 **0 次硬违规**放行。

- **13:40 抵达梵宫圣坛**：**前置 20 分钟安检排队缓冲**，顺利入场观看 14:00~14:20《吉祥颂》；

### 6.3 防御性降级案例：脱离现实诉求的“诚实拒绝”

### 7.2 完整 7 组检索组件受控消融实验

## 第九章：总结与局限性声明

本项目提出并实现了大模型与运筹引擎解耦的混合架构，在受控测试中验证了 96.0% 的事实基准通过率、100% 状态提取率与 0 次路线硬违规，展示了其在垂直物理决策场景中的工程成熟度。

**系统局限性声明**：
1. **基准测试失败用例审计**：在 50 题 Fact Contract 权威基线测试中，48 题严格通过（96.0% 通过率），2 道未通过题经 Trace 审计确认均为 Evaluator 评测器在开放文化表达上的字面判定边界，系统无 API 崩溃与关键数值幻觉；
2. **消融实验的单次受控观察性质**：完整方案取得的 98.0% 准确率明确界定为特定轮次受控消融实验的观察值（`ablation_20260917_013925`），用于证实 Cross-Encoder 重排带来的 $+8.0\%$ 去偏置贡献，不外推为全域开放问答的绝对保证；
3. **数据动态感知限制**：目前部分小径步行时间为几何估算值，后续需接入实时客流传感器；
4. **离线基准与满意度**：96.0% 与 100% 基于严格受控基准集，真实环境下的双盲 A/B 测试有待进一步推进；
5. **模型 Provider 差异披露**：评测配置请求 `deepseek-chat`，实际调度返回 `deepseek-flash`，材料中如实披露以确保实验可复现性。
