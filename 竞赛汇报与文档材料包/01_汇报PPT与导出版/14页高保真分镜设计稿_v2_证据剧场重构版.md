# 灵小禅 14 页竞赛 PPT v2：证据剧场重构版

## 重构结论

现有导出稿的问题不是色彩或字体，而是页面承担的信息过多，导致评委看见了“技术说明书”，没有看见“可信决策产品”。v2 采用“证据剧场”叙事：每页只推动一个判断，主线保持为“听懂游客 → 查准事实 → 算出路线 → 验证可行 → 诚实交付”。

## 视觉总原则

- 视觉气质：国风数智，但以真实景区照片、路线轨迹和证据标签为主，不使用泛赛博装饰。
- 页面节奏：深色场景页、浅色证据页、深色案例页交替，避免 14 页全部使用同一张白底卡片模板。
- 每页只保留一个主视觉焦点，最多三个辅助信息块。
- 标题必须是结论句，不使用“系统架构”“实验结果”这类空标题。
- 算法名称必须和真实作用绑定：RRF 解决多路结果合并，Dijkstra 解决可行路径，Beam Search 解决多景点组合，Validator 负责最终拦截。
- 所有实验和资产数字必须保留证据边界：96.0% 是 50 题权威基线；98.0% 是受控消融观察值；40/40 是场景槽位；60/60 且 0 次物理硬违规是边界路线验证。

## 页面节奏约束

- P1、P3、P11、P12、P14 使用深色或高对比场景，承担情绪和记忆点。
- P5、P7、P9、P10 使用浅色证据页，承担算法和实验解释。
- P2 不再使用三张空白大卡片，必须加入真实图片或极简场景插画。
- P7 不再使用双图表并排；只保留一张可读的横向条形图，另一组数据改为脚注或旁注。
- P11 不再使用四张等权卡片；改为单条时间线，路线、时间、约束和证据绑定在同一条轨迹上。
- P13 不再用长列表解释产品；改为两块真实 UI 样机，中间用一条数据流连接。

## 必须修正的事实口径

当前仓库的审计记录显示 `data/route/edges.json` 实际存在 30 条 edge，而部分规范文本要求 31 条道路。v2 在最终 PPT 中不得把 31 条写成“当前已核验资产”，除非先补齐第 31 条并重跑路线 benchmark；在资产未补齐前，P9 使用“当前路网资产审计口径”脚注，并由项目负责人最终确认对外口径。

## 交付顺序

1. 先按本分镜重写页面文案和素材清单；
2. 再确定每页版式和视觉焦点；
3. 最后修改 PPTX，并重新导出 PDF 逐页检查；
4. 任何页面只有在“评分点、证据、视觉焦点、讲稿”四项同时通过后才算完成。
