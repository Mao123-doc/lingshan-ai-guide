## 实施顺序

1. 冻结当前工作区和材料：记录两份材料、当前ZIP与关键数据SHA-256；保存已有未提交改动，不重置工作区。建立逐页/逐节需求台账，标记当前、缺失、原型、历史证据、后续规划。形成唯一功能清单。
2. 统一接口和状态：由Express管理业务、认证、审计和统计；Python承载向量及确有需要的模型计算；前端负责展示、设备能力和交互。建立共享请求/响应契约，集中处理错误、令牌与取消。先修知识删除误报成功等已确认问题。
3. 恢复游客完整链路：优先文字问答/路线稳定性，再数字人和浏览器语音，再图片、定位和导航。新增模型能力使用明确的配置和超时；不可用时不得生成假成功。
4. 恢复后台闭环：反馈持久化、真实统计、数字人设置与推送。旧组件仅作为实现素材，逐个校验后接回。
5. 补路线与离线能力：返程、演出缓冲和动态重规划先做；离线缓存及求解按需求台账补齐。需要实地测绘、接驳时刻、外部模型凭据的项目明确依赖，不能用程序生成数据代替。
6. 联合验收和冻结：真实浏览器/后端/所需外部服务走查；运行对应算法回归与在线评测；确认性能证据。生成新的工程包、对应版本演示视频和一致性报告；历史ZIP/PPT移出当前交付入口并保留版本索引。

每阶段完成后才进入下一阶段。计划不在依赖和证据未核清前承诺固定工期。

## 完成标准

- 需求台账里的当前交付功能均有真实可操作入口、可调用接口、持久化或计算结果及演示证据；不存在空按钮或仅返回固定成功。
- 历史评测96.0%/98.0%、40/40、60/60保留原始版本归属；新增评测单独记录，失败如实保留，不要求伪造相同数字。
- 原型数据、现场核验项、真实统计和财务测算明确区分。性能仅在指定环境、接口和负载下声明。
- 新包解压独立安装、构建和运行通过；浏览器演示不借用旧dist或旧解压目录；功能、材料、录像和工程manifest能一一对应。
