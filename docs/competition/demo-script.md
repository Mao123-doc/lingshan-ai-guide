# 竞赛演示脚本

## 目标

在 3 分钟内展示“理解复杂需求、给出可执行路线、遇到不可行条件会诚实拒绝、全过程可追踪”。

## 主场景

输入：

> 我带腿脚不方便的妈妈，现在是 13:00，在景区入口，只有三小时，还想看两点的《吉祥颂》，应该怎么走？

展示顺序：

1. 展示 Scene State：入口、13:00、180 分钟、行动受限、必须观看 14:00《吉祥颂》。
2. 展示路线时间线：到达目标点、等待、演艺、总步行与总耗时。
3. 展示每个景点的证据来源和 confidence。
4. 展示 Trace：Rewrite、Vector、Structured、Keyword、Rerank、LLM 的 configured/executed/status。
5. 修改为轮椅 + 20 分钟 + 必须去灵山梵宫，展示系统返回不可行原因，而不是编造路线。

## 评委问答准备

问：为什么不让大模型直接规划？

答：语言理解和路线可行性是不同问题。模型负责抽取与解释，时间窗、连通性、行动能力和必达点由确定性校验器裁决，结果可复现、可审计。

问：三路检索为什么都要保留？

答：语义检索处理表达差异，结构化检索保证字段事实，关键词检索保留精确命中；Trace 使它们可以独立验证和消融。

问：数据可靠吗？

答：知识来源和哈希都记录；路线数据中的 estimated 字段不冒充官方实时数据，现场部署前需要运营方核验。
