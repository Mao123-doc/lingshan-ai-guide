# 竞赛创新点与差异化表达

## 1. 从问答升级为可执行决策

普通景区问答通常只返回一段介绍。本项目把游客请求拆成可验证的约束：当前在哪里、什么时候出发、剩余多久、是否行动不便、必须看什么、演艺场次是什么。最终输出不是“推荐几个景点”，而是带时间线和失败原因的可执行计划。

## 2. LLM 与确定性规划器职责分离

LLM 擅长理解口语和组织说明，但不适合独自计算可达性、开放时间、演艺冲突和行动能力约束。项目将这些硬约束交给确定性 Route Validator / Planner，并保留每一步的证据和拒绝原因，降低幻觉风险。

## 3. 三层检索可解释而非黑盒

Vector、Structured、Keyword 三路分别代表语义召回、字段事实和精确词匹配。三路并行、统一候选协议、RRF 融合，Trace 记录每层是否真实执行、召回数量和最终排序，后续可以做有证据的消融，而不是只比较一个最终分数。

## 4. “不可行”也是产品能力

当轮椅用户在时间预算内无法到达必达点、演艺场次已无法满足或缺少关键当前时间时，系统返回明确的不可行原因。这比强行生成一条看似完整但无法执行的路线更适合景区场景。

## 5. 可审计证据链

每个离线结果绑定 Gold 集、知识库哈希、配置、运行结果和 Git SHA；路线证据返回景点来源与置信级别。评委可以复现指标，也可以看到系统在哪些条件下失败。

## 不应夸大的点

当前证据支持“可解释、可复现、约束可验证”，不支持“全网实时导航”“真实用户满意度显著提升”或“所有设施信息官方准确”。这些需要后续现场数据和用户实验。
